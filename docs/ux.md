# UX — โต๊ะตรวจงานโซลาร์รายเดือน

ปรับปรุง: 9 กันยายน 2026
อ้างอิง: [DESIGN.md](../DESIGN.md) · [UI](ui.md) · [กติกาข้อมูล](domain-rules.md)
ทุกหัวข้อกำกับสถานะ: **[มี]** ใช้งานได้จริงวันนี้ · **[บางส่วน]** มีแต่ยังไม่ครบ · **[เสนอ]** ยังไม่มี ห้ามทำให้ดูเหมือนมี

## 1. ผู้ใช้และผลลัพธ์ที่ต้องได้

ผู้ดูแลไม่ได้เป็นวิศวกรโซลาร์ ทำงานรอบเดือน ส่งงานช่างผ่าน LINE และไม่มีเวลากรอกฟอร์มยาว เป้าหมายคือใช้เวลาไม่เกินสิบถึงสิบห้านาทีต่อเดือนก็รู้ว่าควรให้ช่างไปดูไซต์ไหน เพราะอะไร และงานที่แจ้งไปแล้วคืบหน้าถึงไหน

เส้นทางหลัก:

เลือกเดือน → ดูว่าข้อมูลครบไหม → ดูยอดและแนวโน้มเทียบปีก่อน → เปิดรายการที่ควรตรวจ → อ่านหลักฐานของไซต์นั้น → คัดลอกข้อความส่ง LINE → เมื่อช่างตอบกลับก็บันทึกผลตรวจ → อ่านสรุปเดือน

ระบบต้องยอมให้ผู้ใช้ออกจากเส้นทางกลางทางแล้วกลับมาต่อได้ โดยเดือนและขอบเขตไม่หลุด

## 2. คำที่ใช้บนหน้าจอ

ใช้คำเดียวกันทุกหน้า ห้ามสลับ:

| ใช้คำนี้ | หมายถึง | ห้ามใช้ |
|---|---|---|
| ไฟที่ผลิตได้ (หน่วย) | inverter yield รายเดือน 1 หน่วย = 1 kWh | ยอดผลิตสด, พลังงานปัจจุบัน |
| ไฟที่ใช้เอง / ไฟที่ส่งออก | self-consumption / export | โหลด, ขาย |
| กำลังติดตั้ง (kWp) | ขนาดที่ติดตั้ง | กำลังไฟ |
| ไม่มีข้อมูล | ไม่มีค่าที่ใช้ได้ | 0, ว่าง, ปกติ |
| ต้นทางรายงานศูนย์ | ไฟล์ระบุค่า 0 จริง | ไม่มีข้อมูล, เครื่องดับ |
| ยังประเมินไม่ได้ | หลักฐานไม่พอจัดระดับ | ปกติ, ไม่พบปัญหา |
| ยังไม่ยืนยัน | ข้อสันนิษฐาน | สาเหตุ, พบว่า |
| เดือนของรายงาน | เดือนที่ข้อมูลพูดถึง | เดือนล่าสุด |
| เดือนของทะเบียนไซต์ | เดือนของไฟล์ที่ยืนยันจำนวนไซต์ | จำนวนไซต์ปัจจุบัน |
| เวลานำเข้าสำเร็จ | เวลาที่ไฟล์เข้าระบบ | เวลาอัปเดตล่าสุดของไซต์ |

ห้ามใช้คำว่า "เครื่องเสีย" "อันตราย" "ปกติแน่นอน" ในรายงานรายเดือน เพราะรายงานรายเดือนพิสูจน์เรื่องพวกนี้ไม่ได้

## 3. โครงหน้าร่วม (ทุกหน้า)

**[มี]** แถบบนแนวนอน 4 เมนู: ภาพรวม · ไซต์ทั้งหมด · รายการตรวจสอบ · รายงานและข้อมูล เมนูที่เปิดอยู่ต้องบอกด้วยข้อความหรือ `aria-current` ไม่ใช่สีเดียว

**[มี]** แถบบริบทใต้เมนู แสดงพร้อมกันสามอย่าง: เดือนที่เลือก · ขอบเขตไซต์ (ทะเบียนต้นทาง / รวมประวัติ) · ความครบถ้วนของเดือนนั้น

**[มี]** แถบที่มาข้อมูล แสดง เดือนของทะเบียนไซต์ และ เวลานำเข้าสำเร็จ พร้อมประโยคว่านี่ไม่ใช่สถานะอุปกรณ์สด และไม่ใช่สถานะซิงก์ล่าสุดของทั้งระบบ

**[มี]** เดือนและขอบเขตอยู่ใน URL จึงคงอยู่เมื่อกดเข้าไซต์ กดย้อนกลับ หรือแชร์ลิงก์

กติกา: เปลี่ยนเดือนแล้วทุกส่วนที่อิงเดือนต้องเปลี่ยนตาม ส่วนที่ไม่อิงเดือน (เช่น งานค้างข้ามเดือน) ต้องติดป้ายช่วงเวลาของตัวเองให้ชัด

## 4. หน้า 1 — ภาพรวม

ลำดับเนื้อหาจากบนลงล่าง:

1. **[มี] แถบความครบถ้วน** — มีค่าผลผลิตกี่ไซต์จากกี่ไซต์ในขอบเขต, มีรายงานกี่ไซต์, ขาดรายงานกี่ไซต์, ขาดค่าผลผลิตกี่ไซต์ ตัวเลขสี่ตัวนี้แยกกันคนละความหมาย ห้ามยุบเป็นตัวเดียว
2. **[มี] ยอดไฟที่ผลิตได้ของเดือน** พร้อมหมายเหตุว่าครอบคลุมกี่ไซต์ ถ้าไม่ครบต้องเห็นทันที
3. **[มี] กราฟเส้น 12 เดือน** เปิด/ปิดการเทียบปีก่อนได้ กดจุดเดือนเพื่อเปลี่ยนเดือนที่ดู ค่าอ่านเป็นข้อความใต้กราฟด้วย
4. **[เสนอ] กราฟแท่งจับกลุ่มเทียบปีต่อปี** แท่งคู่ต่อเดือน (ปีนี้ / ปีก่อน) สำหรับคนที่อ่านแท่งง่ายกว่าเส้น สลับดูเส้น/แท่งได้ ใช้ข้อมูลชุดเดียวกับกราฟเส้น
5. **[มี] การ์ดไซต์ที่ควรดู** จำกัดสี่ใบ เรียงสัญญาณจากการประเมินเดิมก่อน แล้วต่อด้วยไซต์ที่ข้อมูลขาด แต่ละใบมีชื่อไซต์ ป้ายสถานะพร้อมข้อความ เหตุผลสั้น และลิงก์ดูรายละเอียด
6. **[เสนอ] แถวงานที่แจ้งช่างแล้วและรออยู่** ให้แสดงเฉพาะเมื่อมีที่เก็บสถานะจริง ตอนนี้ต้องเขียนตรง ๆ ว่ายังไม่มีระบบบันทึกติดตาม

กติกา: กดตัวเลขความครบถ้วนหรือการ์ดแล้วเปิดหน้ารายการที่กรองไว้ให้ตรงกัน ห้ามเปลี่ยนฐานยอดรวมเงียบ ๆ ถ้าเดือนที่เลือกไม่มีรายงาน ให้บอกว่าเดือนนั้นไม่มีข้อมูล และเสนอเดือนล่าสุดที่มีเป็นปุ่มแยก ห้ามสลับเดือนให้เองเงียบ ๆ และห้ามสรุปว่าทุกไซต์ปกติ

## 5. หน้า 2 — ไซต์ทั้งหมด และรายละเอียดไซต์

**รายการไซต์ [มี]** ค้นหาชื่อ, กรองตามชนิดข้อมูล (ทั้งหมด / ขาดค่าผลผลิต / มีสัญญาณจากการประเมินเดิม), แบ่งหน้า จำนวนผลค้นหาต้องแยกจากจำนวนไซต์ในขอบเขต และเขียนให้ชัดว่าตัวกรองเปลี่ยนแค่แถวที่เห็น

**[บางส่วน]** ตัวกรองสถานะเปิดใช้งานไซต์และสถานะงานติดตามยังไม่มีข้อมูลรองรับ ต้องเขียนบอกในหน้า ไม่ใส่ตัวกรองที่กรองไม่ได้จริง

**แถบไซต์ด้านซ้าย [มี]** กว้างประมาณ 250px ค้นหาและสลับไซต์ได้ทันทีในหน้ารายละเอียด ไซต์ที่เลือกอยู่บอกด้วยข้อความไม่ใช่สีเดียว

**ลำดับในหน้ารายละเอียดไซต์:**

1. **[มี]** ชื่อไซต์ + เดือน + ขอบเขต + ความครบถ้วน วางแถวเดียวกันบน desktop เพื่อไม่ผลักกราฟลงล่าง
2. **[มี] กราฟผลผลิตย้อนหลังของไซต์** มาก่อนข้อความยาว กราฟกว้างเต็ม ปรับตามความกว้างจริงของจอ ช่องไม่มีข้อมูลเป็นช่องว่าง
3. **[มี]** สิ่งที่พบเดือนนี้ — ค่าจากรายงาน และการเทียบฐาน (เดือนก่อน / เดือนเดียวกันปีก่อน) ระบุชนิดฐาน ถ้าฐานเป็นศูนย์หรือขาดให้บอกว่าเทียบเปอร์เซ็นต์ไม่ได้
4. **[มี]** ข้อเสนอจาก AI ในบล็อกของตัวเอง ติดป้าย "ข้อสันนิษฐาน ยังไม่ยืนยัน" สรุปเห็นได้ทันที รายละเอียดหลักฐานอยู่ใน disclosure และมีประวัติผลที่บันทึกไว้แยก
5. **[มี]** ข้อความสำหรับคัดลอกส่ง LINE
6. **[มี]** ประวัติซ่อมจริง + ฟอร์มเพิ่มบันทึกซ่อม
7. **[มี]** ค่าพลังงานอื่น ไฟที่ใช้เอง ไฟที่ส่งออก สัดส่วนใช้เอง
8. **[มี]** รายละเอียดเทคนิคและตารางรายเดือนใน disclosure ไม่บังข้อมูลจำเป็น
9. **[บางส่วน]** ป้ายระดับที่มาจากการประเมินเดิม ต้องเขียนว่า "การประเมินเดิม ยังไม่ใช่เกณฑ์ความสำคัญใหม่"

กติกา: ปุ่มกลับต้องรักษาเดือน ขอบเขต ตัวกรอง และคำค้นจากหน้าก่อน ถ้าไซต์นี้ไม่มีข้อมูลเดือนที่เลือก ให้บอกตรง ๆ ว่าเดือนไหนขาด ไม่เด้งไปเดือนอื่นเอง

## 6. หน้า 3 — รายการตรวจสอบ

แยกสองกลุ่มให้ชัด เพราะแก้ต่างกัน:

- **ปัญหาข้อมูล** — ไม่มีรายงาน, ขาดค่าจำเป็น, ค่าขัดกันเอง แก้ที่ต้นทางหรือการนำเข้า
- **สัญญาณผลผลิต** — ผลผลิตศูนย์ทั้งเดือน, ลดลงมาก, ลดต่อเนื่อง ต้องให้คนไปดู

แต่ละรายการต้องมี **[มี]**: ชื่อไซต์ · เดือน · ชนิดสัญญาณ · ข้อเท็จจริงพร้อมค่าที่เทียบและชนิดฐาน · แหล่งข้อมูลและข้อจำกัด · แนวทางตรวจเรียงจากถูกไปแพง (ตรวจความครบของรายงาน → ตรวจประวัติ → ให้ช่างไปหน้างาน)

**[มี — 9 กันยายน 2026]** บันทึกเปิดงานจากเดือนต้นทาง สถานะติดตาม ผู้บันทึก เวลา หมายเหตุ และผลตรวจจริงแล้ว ดูงานเดิมข้ามเดือนและเปิดติดตามต่อได้ในงานเดิม **[เสนอ]** แนบรูปและเพิ่ม snapshot หลักฐานเดือนใหม่เข้าไปในงานเดิม ยังไม่เปิดใช้

**สามระดับที่แยกกันไม่ปนกัน:**

1. ความสำคัญ — เร่งตรวจสอบ / ควรตรวจสอบ / เฝ้าติดตาม / ไม่พบสัญญาณผิดปกติ / ยังประเมินไม่ได้
2. คุณภาพข้อมูล — ครบ / ขาดรายงาน / ขาดค่าจำเป็น / ค่าขัดกัน / รอยืนยัน
3. สถานะงาน — รอตรวจ / แจ้งช่างแล้ว / ได้ผลตรวจแล้ว

แจ้งช่างแล้วไม่ลดความสำคัญเอง ความสำคัญเปลี่ยนเมื่อหลักฐานเปลี่ยน ไม่ใช่เมื่อมีคนกดปุ่ม

เกณฑ์ตัวเลขของสามระดับความสำคัญแรกยังไม่อนุมัติ ห้ามใส่ค่าเองแล้วอ้างว่าเป็นนโยบาย ระหว่างนี้แสดงผลจากการประเมินเดิมพร้อมป้ายกำกับ

## 7. หน้า 4 — รายงานและข้อมูล

**ส่วนรายงาน [มี]**: เดือน · ขอบเขต · ยอดไฟที่ผลิตได้ · ไซต์ในขอบเขต · ไซต์ที่มีค่าผลผลิต · ไซต์ที่มีสัญญาณจากการประเมินเดิม · ไซต์ที่ข้อมูลขาด · เวลาที่อ่านข้อมูลมาสรุป

**[เสนอ]** จำนวนงานใหม่ งานค้าง งานที่ได้ผลตรวจ และรายการสาเหตุที่ช่างยืนยัน ต้องรอระบบติดตาม ตอนนี้เขียนว่ายังไม่มีข้อมูลติดตามจริง

**[เสนอ]** ส่งออกไฟล์รายงาน ยังไม่เลือกรูปแบบและยังไม่มีรุ่นข้อมูลที่รับรองได้ ห้ามใส่ปุ่มดาวน์โหลดที่ไม่ทำงาน

**ส่วนนำเข้าข้อมูล [มี]**: เลือกไฟล์ Plant Report → ระบบอ่านไฟล์และบอกจำนวนไซต์ที่พบ → ผู้ใช้ยืนยันเดือนของรายงาน → กดนำเข้าและเริ่มวิเคราะห์อัตโนมัติ → เห็นสถานะคิว AI ของเดือนนั้น (รอคิว / กำลังวิเคราะห์ / บันทึกผลแล้ว / ไม่สำเร็จ)

ข้อความบังคับในส่วนนี้: การนำเข้าอาจอัปเดตข้อมูลเดือนที่มีอยู่ · เส้นทางนำเข้าหน้าเว็บนี้ยังไม่ครอบทั้งไฟล์เป็นทรานแซกชันเดียว จึงอาจอัปเดตไปบางแถวถ้าพลาดกลางทาง · จำนวนงานในคิวไม่ใช่จำนวนไซต์ในขอบเขตแดชบอร์ด · ถ้าเข้าคิวไม่สำเร็จให้บอกว่านำเข้าแล้วแต่คิวไม่สำเร็จ

**ส่วนที่มาข้อมูล [มี]**: แหล่งข้อมูล · เดือนของทะเบียนไซต์ · เวลานำเข้าทะเบียน
**[เสนอ]**: ประวัติซิงก์สำเร็จ/ล้มเหลวบนหน้าจอ · รายการความขัดแย้งของค่าที่แก้ไว้ · ฟอร์มแก้ค่ารายเดือน · การตั้งเวลาซิงก์

## 8. การดึงข้อมูลย้อนหลังใหม่ทั้งชุด (ยังไม่ทำ)

ผู้ใช้ต้องการดึงรายงานรายเดือนย้อนหลังใหม่ทั้งหมดจาก Reports → Plant Report → By plant → By month แล้วค่อยแทนข้อมูลรายเดือนเดิม เอกสารนี้ **ไม่ยืนยันว่าดึงมาแล้ว**

หน้าจอที่ต้องมีเมื่อทำจริง เป็นตัวช่วยสี่ขั้น เห็นตำแหน่งตัวเองตลอด:

1. **เตรียม** — เลือกช่วงเดือน เห็นรายการเดือนที่จะดึง และเห็นว่ามีข้อมูลเดิมอยู่เดือนไหนแล้ว
2. **ตรวจไฟล์** — ตารางต่อเดือน: เดือนตรงไหม, เมนูถูกไหม, จำนวนไซต์ตรงยอดรวมไหม, มีค่า inverter yield ไหม, ชื่อซ้ำไหม เดือนที่ไม่ผ่านต้องหยุดที่นี่และบอกเหตุผล
3. **เทียบก่อนแทน** — ต่อเดือนบอกว่าค่าต่างเท่าไร ไซต์ไหนเพิ่ม ไซต์ไหนหาย และค่าที่ผู้ใช้เคยแก้มือชนกับค่าใหม่ตรงไหน
4. **อนุมัติและแทน** — ผู้ใช้อนุมัติทีละชุด ระบบเก็บค่าต้นทางเดิม เวลาแทน ผู้สั่ง เหตุผล และประเมิน/สรุปเดือนที่กระทบใหม่

กติกา: ข้อมูลที่พักไว้ยังไม่นับในยอดใด ๆ · ไซต์ที่หายจากไฟล์ใหม่ไม่ถูกลบ แต่ติดป้ายว่าไม่พบในต้นทาง · ดาวน์โหลดล้มเหลวห้ามรายงานว่าอัปเดตสำเร็จ · ข้อมูลย้อนหลังชุดใหม่ไม่ใช่สถานะอุปกรณ์วันนี้

## 9. AI และผลตรวจของช่าง

**[มี]** หลังนำเข้าสำเร็จและสร้างสรุปใหม่สำเร็จ ระบบเข้าคิววิเคราะห์ทุกไซต์ในไฟล์อัตโนมัติ ทำงานเบื้องหลัง ไม่ต้องเปิดหน้ารอ ปิดเครื่องแล้วเปิดใหม่คิวยังอยู่ เปิดหน้าอ่านผลที่บันทึกไว้ไม่สร้างคำขอใหม่

**[มี]** บันทึกซ่อมจริงเก็บลงฐานข้อมูล: วันที่เกิดเหตุ ประเภท สิ่งที่พบ สิ่งที่ทำ ผลลัพธ์ ผู้บันทึก วันที่ห้ามเป็นอนาคต

**เส้นแบ่งที่ต้องเห็นด้วยตา:**

- ข้อเสนอ AI อยู่บล็อกหนึ่ง บันทึกช่างอยู่อีกบล็อก ห้ามผสม
- ข้อเสนอ AI ติดป้าย "ยังไม่ยืนยัน" ไม่เปลี่ยนคะแนน ไม่เปลี่ยนสถานะงาน ไม่เข้าไปในข้อความ LINE เอง
- ผลลัพธ์ที่เลือกได้: ยังไม่ทราบสาเหตุ / ต้องดำเนินการต่อ / ช่างแจ้งว่าแก้แล้ว / ยืนยันจบแล้ว
- "ช่างแจ้งว่าแก้แล้ว" ไม่เท่ากับ "ยืนยันจบแล้ว" การยืนยันต้องมีผู้บันทึกและหลักฐาน
- ไซต์ฟื้นเดือนถัดไปเป็นข้อมูลประกอบ ไม่ใช่ข้อพิสูจน์สาเหตุ
- ไซต์หายจากไฟล์ไม่ปิดงานเอง

**[บางส่วน]** บันทึกซ่อมยังแก้ไม่ได้ ลบไม่ได้ แนบรูปไฟล์ไม่ได้ ยังไม่มีระบบยืนยันตัวตน ชื่อผู้บันทึกคือชื่อที่กรอกเอง การเปิดเขียนจำกัดเฉพาะระบบบนเครื่อง ซึ่งเป็นการกันเบื้องต้น ไม่ใช่ระบบสิทธิ์

## 10. LINE

**[มี]** ปุ่มคัดลอกสร้างข้อความ: ชื่อไซต์ · เดือน · ข้อเท็จจริงจากรายงาน · ประโยคว่ายังไม่ยืนยันสาเหตุ · คำขอให้ตรวจสามข้อ (ความครบของรายงาน ประวัติหยุดทำงาน ข้อมูลแจ้งเตือน) · คำถามปิดท้ายว่าพบอะไร ทำอะไรไป ต้องตรวจต่อไหม

ไม่มีรหัสผ่านหรือข้อมูลเชื่อมต่อในข้อความ **การคัดลอกไม่ส่ง LINE และไม่เปลี่ยนสถานะเป็นแจ้งแล้ว** ข้อความยืนยันหลังกดต้องเขียนตรงว่า "คัดลอกแล้ว ยังไม่ได้ส่ง LINE และไม่ได้เปลี่ยนสถานะงาน"

**[มี]** บันทึก “แจ้งช่างแล้ว” ในงานตรวจ เป็นการยืนยันแยกจากปุ่มคัดลอก ระบุผู้บันทึกและแจ้งใครผ่านช่องทางใด เก็บประวัติจริง และไม่ส่ง LINE

## 11. สถานะหน้าจอที่ต้องออกแบบให้ครบ

| สถานะ | ต้องเป็นอย่างไร |
|---|---|
| กำลังโหลด | โครงร่างในตำแหน่งจริง มี `role="status"` บอกว่ากำลังโหลดอะไร ห้ามแสดง 0 ระหว่างรอ |
| โหลดไม่ได้ | บอกส่วนที่ล้มเหลวและปุ่มลองใหม่ ห้ามแทนด้วยยอด 0 ห้ามแสดงหน้าว่างเปล่า |
| ไม่มีข้อมูลเดือนนั้น | บอกว่าเดือนไหนไม่มี เสนอเดือนล่าสุดที่มีเป็นปุ่มแยก ห้ามสรุปว่าทุกไซต์ปกติ |
| ค้นหาไม่พบ | บอกว่าไม่พบตามคำค้น/ตัวกรอง พร้อมปุ่มล้างตัวกรอง จำนวนไซต์ในขอบเขตยังแสดงอยู่ |
| ข้อมูลบางส่วน | บอกความครอบคลุมเป็นจำนวนไซต์ ยอดรวมติดหมายเหตุ กราฟช่องว่างไม่เติมศูนย์ |
| ไม่มีฐานเปรียบเทียบ | บอกว่าเทียบเปอร์เซ็นต์ไม่ได้ ใช้ผลต่างหน่วยเมื่อทำได้ |
| เดือนปัจจุบัน/อนาคต | ติดป้ายว่าเป็นข้อมูลระหว่างเดือน ไม่ใช่ยอดเต็มเดือน ห้ามเทียบตรงกับเดือนเต็ม |
| บันทึกไม่สำเร็จ | ข้อความผิดพลาดชัด `role="alert"` **ข้อความที่พิมพ์ไว้ต้องยังอยู่** |
| บันทึกสำเร็จ | ยืนยันได้เฉพาะเมื่อที่เก็บจริงตอบสำเร็จ |
| เข้าคิว AI ไม่สำเร็จ | บอกว่านำเข้าแล้วแต่คิวไม่สำเร็จ ห้ามรายงาน AI สำเร็จ |
| ชื่อไซต์ไทยยาว | ขึ้นบรรทัดใหม่ ไม่ตัดคำหาย ไม่ทำให้หน้าล้นแนวนอน |
| ยังไม่มีทะเบียนที่ยืนยันจำนวน | ใช้รายงานเดือนที่เลือกแทน และเขียนบอกว่ายังไม่มีทะเบียนยืนยัน |

## 12. คีย์บอร์ดและการเข้าถึง

- ลำดับ Tab ตามการอ่าน: เมนู → ตัวควบคุมเดือน/ขอบเขต → เนื้อหา
- ทุกตัวควบคุมเห็น focus ชัด ไม่ใช้เฉพาะสีจาง
- ปุ่มคัดลอก LINE ทำงานด้วย Enter/Space และไม่ยิงคำขอไปเซิร์ฟเวอร์
- disclosure (รายละเอียดเทคนิค/หลักฐาน AI) เปิดปิดด้วยคีย์บอร์ด และบอกสถานะเปิด/ปิด
- กราฟมีทางอ่านที่ไม่ใช้เมาส์: ปุ่มเลือกเดือน + ค่าที่อ่านออกเสียงผ่าน `aria-live` + ตารางค่าใน disclosure
- ตัวกรอง ตาราง และรายการมีชื่อกำกับด้วย `aria-label` ที่บอกว่ากรองอะไร
- ปุ่มสัมผัสอย่างน้อย 44×44px บนมือถือ
- สถานะไม่สื่อด้วยสีเดียว ต้องมีข้อความหรือไอคอนกำกับ
- ตารางเทคนิคอนุญาตเลื่อนแนวนอนได้เฉพาะในกรอบของตัวเอง พร้อมสัญญาณว่าเลื่อนได้ ห้ามซ่อน overflow ของทั้งหน้า

## 13. ที่มาของข้อมูลที่ต้องเห็นบนหน้าจอ

ทุกตัวเลขที่ตัดสินใจได้ต้องตอบได้ว่ามาจากไหน:

- **แหล่ง** Huawei Plant Report รายเดือน (By plant / By month)
- **เดือนของรายงาน** ที่ค่านั้นอ้างถึง
- **ขอบเขตไซต์** ที่ใช้นับ (ทะเบียนต้นทาง / รวมประวัติ) และจำนวนไซต์ในขอบเขตนั้น
- **ความครอบคลุม** ค่านี้รวมกี่ไซต์จากกี่ไซต์
- **ชนิดฐานเปรียบเทียบ** เดือนก่อน / เดือนเดียวกันปีก่อน / ค่าเฉลี่ยช่วงที่ระบุ
- **เวลานำเข้าสำเร็จ** และ **เดือนของทะเบียนไซต์** ซึ่งไม่ใช่สิ่งเดียวกับเวลาที่ไซต์เดินล่าสุด
- **ที่มาของข้อเสนอ AI** รุ่นโมเดล เวลา และหลักฐานที่ใช้ พร้อมป้ายว่ายังไม่ยืนยัน
- **ผู้บันทึกและเวลา** ของบันทึกซ่อมทุกรายการ

ข้อมูลที่ยืนยันจากการแทนชุดรายงานวันที่ 9 กันยายน 2026: มิถุนายน 2023 – สิงหาคม 2026 รวม 39 เดือน ทะเบียนล่าสุดสิงหาคม 2026 หน้าจอต้องอ่านเดือนทะเบียนและจำนวนไซต์จาก API และไม่ทำให้เข้าใจว่าเป็นสถานะอุปกรณ์วันนี้

## 14. เกณฑ์ตรวจรับ UX

ถือว่าผ่านเมื่อทำได้ทุกข้อ:

1. จากหน้าแรก เลือกไซต์ที่ควรตรวจและเห็นหลักฐานของไซต์นั้นได้ภายในสองครั้งที่กด
2. อ่านหน้ารายละเอียดแล้วบอกได้ว่าอะไรคือข้อเท็จจริงจากรายงาน อะไรคือข้อสันนิษฐาน อะไรคือสิ่งที่ช่างบันทึก
3. เปลี่ยนเดือนแล้วทุกส่วนที่อิงเดือนเปลี่ยนตาม ส่วนที่ไม่อิงเดือนติดป้ายช่วงเวลาของตัวเอง
4. เข้าไซต์แล้วกดย้อนกลับ เดือน ขอบเขต ตัวกรอง และคำค้นยังอยู่
5. เปิดกราฟเทียบเดือนเดียวกันปีก่อนได้ (วันนี้: เส้น + เส้นประปีก่อน · เมื่อเพิ่มแท่งจับกลุ่มแล้วต้องใช้ข้อมูลชุดเดียวกัน) และอ่านค่าได้เป็นข้อความโดยไม่ใช้เมาส์
6. เดือนที่ไม่มีข้อมูลไม่แสดงเป็นศูนย์ และไม่ถูกสรุปว่าปกติ
7. ฐานเป็นศูนย์หรือขาด ไม่มีเปอร์เซ็นต์โผล่ที่ไหนเลย
8. ค้นหา/กรองไม่เปลี่ยนจำนวนไซต์ในขอบเขตและไม่เปลี่ยนฐานยอดรวม
9. คัดลอก LINE ได้ด้วยคีย์บอร์ด และข้อความยืนยันบอกว่ายังไม่ได้ส่งและไม่ได้เปลี่ยนสถานะ
10. บันทึกซ่อมสำเร็จเก็บได้จริงและอ่านย้อนหลังได้ · บันทึกล้มเหลวไม่ทำให้ข้อความที่พิมพ์หาย
11. ข้อเสนอ AI ไม่ปนกับบันทึกช่าง และติดป้ายว่ายังไม่ยืนยันทุกที่
12. ที่ 390px ไม่มีการเลื่อนแนวนอนของทั้งหน้า ชื่อไซต์ไทยยาวยังอ่านครบ ข้อมูลหลักไม่ต้องเลื่อนตารางเพื่อดู
13. ที่ 1440px และ zoom 200% ยังอ่านและใช้งานได้
14. ไม่มีปุ่มหรือตัวกรองที่กดแล้วไม่เกิดอะไร ความสามารถที่ยังไม่มีอยู่ในรายการ "ยังไม่เปิดใช้งาน"
15. ไม่มีสถานะบันทึก ส่ง หรือซิงก์สำเร็จที่ไม่ได้เกิดขึ้นจริง

## 15. รายการค้างและสิ่งที่ยังกดไม่ได้

**ยังไม่เปิดใช้งานในรอบนี้** (แสดงเป็นรายการ ไม่ใช่ปุ่มตาย): แก้ค่ารายเดือน · ทบทวนความขัดแย้งของค่าที่แก้ · ประวัติซิงก์บนหน้าจอ · ตั้งเวลาซิงก์อัตโนมัติ · ส่งออกไฟล์รายงาน · บันทึกสถานะติดตามงาน · แนบรูปประกอบ · แก้/ลบบันทึกซ่อม · ระบบผู้ใช้และสิทธิ์

**ต้องตัดสินใจก่อนพัฒนาต่อ**: เกณฑ์ตัวเลขของระดับความสำคัญชุดใหม่ · แหล่งข้อมูลสถานะเปิดใช้งานไซต์ · รหัสไซต์ถาวรและชื่อพ้อง · ผู้มีสิทธิ์แก้ข้อมูลและปิดงาน · รูปแบบไฟล์ส่งออก · เครื่องที่รันซิงก์ต่อเนื่อง · ระยะเก็บรูป · เพดานค่าใช้จ่าย AI

**ห้ามทำในรอบนี้**: เปลี่ยนสูตรคะแนนหรือเกณฑ์แจ้งเตือน · map ป้ายระดับเดิมไปเป็นระดับใหม่ · ลบไซต์หรือรายงานเพื่อให้เลขตรง · สร้างผลตรวจช่างหรือสถานะซิงก์ปลอม
