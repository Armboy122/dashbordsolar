# ระบบบันทึกการตรวจสอบ

เปิดรายละเอียดไซต์ → งานตรวจที่บันทึกจริง → เปิดงานจากเดือนที่เลือก ระบุเรื่อง ประเภท ผู้บันทึก

- รอตรวจ → แจ้งช่างแล้ว: ยืนยันเองหลังติดต่อช่าง ระบุช่องทางในหมายเหตุ ไม่ส่ง LINE
- รอตรวจ/แจ้งช่างแล้ว → ได้ผลตรวจ: ระบุวันที่ สิ่งที่ช่างพบ วิธีดำเนินการ ผลหลังแก้ และหลักฐานหากยืนยันผล
- ได้ผลตรวจ → รอตรวจ: เปิดติดตามงานเดิมต่อ ประวัติเดิมยังอยู่ ได้ผลตรวจไม่แปลว่าซ่อมสำเร็จ
- การคัดลอก LINE ไม่มีผลต่อสถานะ ไม่สร้างงานเองจาก scoring หรือการนำเข้า

งานผูก `sites.id` + ประเภท ขณะรอตรวจ/แจ้งแล้วมีได้หนึ่งงานต่อประเภท ป้องกันการเปิดซ้ำ งานใหม่หลังได้ผลเก็บรหัสงานครั้งก่อนในหลักฐานโดยไม่อ้างว่าเป็นสาเหตุเดียวกัน

แสดงงานทุกเดือนของไซต์ หรือทุกไซต์ทุกเดือนในหน้ารายการตรวจสอบ แยกจาก scope ของรายงานที่เลือกชัดเจน โหลดล่าสุดไม่เกิน 200 งานโดยให้งานที่ยังไม่ได้ผลมาก่อน มีป้ายเมื่อเกินขีดจำกัด จำนวนนี้ไม่ใช่จำนวนไซต์

## การบันทึก

เพิ่มตาราง `solar_inspections` และ `solar_inspection_events` ผ่าน migration `migrations/20260909-inspections.sql` ไม่แก้ schema รายงานเดิมหรือ scoring

`GET /api/inspections?site=ชื่อไซต์` อ่านงานและ audit; ไม่ส่ง site = ทุกไซต์
`POST /api/inspections` รับ create หรือ transition ตรวจข้อมูลและจำกัดการเขียนบน localhost แบบเดียวกับประวัติซ่อมเดิม

หลักฐานเปิดงานอ่านฝั่งเซิร์ฟเวอร์จากรายงานจริง ณ เวลานั้น: เดือน มีรายงานหรือไม่ ผลผลิต null/zero แยกกัน ไม่รับตัวเลขที่ frontend อ้างเอง

บันทึกสถานะ + event + ประวัติซ่อมจากผลตรวจใน transaction เดียว ใช้ row lock/version กันแก้ชน ใช้ request UUID + hash กัน retry ซ้ำหรือใช้รหัสคำขอเดิมกับข้อมูลที่เปลี่ยนแล้ว ไม่เขียนข้อมูลแบบ optimistic บนหน้าเว็บ

ผลตรวจเก็บใน `solar_maintenance_records` ด้วย จึงเข้าสู่บริบท Gemini ในการวิเคราะห์ครั้งถัดไปตามกติกาวันที่เดิม (ไม่เกินเดือนที่เลือก สูงสุด 50 รายการ) ไม่เรียก Gemini หรือทำให้ผล AI เดิมดูเหมือนอัปเดตเองเมื่อบันทึก

## ติดตั้งและตรวจ

- `npx tsx scripts/verify-inspections.ts`: ทดสอบ SQL ใน schema แยก และ rollback ทั้ง schema ไม่ทิ้งงาน/ช่างตัวอย่างในข้อมูลจริง
- `npx tsx scripts/init-inspections.ts`: เพิ่มตารางเมื่อยังไม่มี ใช้ transaction
- `npm run typecheck`, `npm test`, `npm run build`

## ข้อจำกัด

ชื่อผู้บันทึกเป็นข้อความที่ผู้ใช้กรอก ไม่ใช่บัญชีที่พิสูจน์ตัวตน การจำกัด localhost ไม่ใช่ระบบสิทธิ์สำหรับเปิดสาธารณะ
ยังไม่มีรูปแนบ แก้/ลบ audit, pagination เกิน 200 งาน, สรุปงานรายเดือน หรือเพิ่ม snapshot เดือนใหม่ในงานเดิม (ใช้หมายเหตุติดตามได้)
ผลตรวจที่ได้ไม่ปิดปัญหาอัตโนมัติ ผู้ใช้เปิดติดตามต่อเองได้ ผลผลิตฟื้นหรือไซต์หายไม่เปลี่ยนงานเอง
