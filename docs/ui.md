# UI — แดชบอร์ดที่อ่านง่าย

สถานะ: แนวทางเป้าหมาย ใช้ร่วมกับ [UX](ux.md) และ [กติกาข้อมูล](domain-rules.md)

## ทิศทางภาพรวม
ใช้พื้นขาวหรือเทาอุ่น ตัวอักษรสีเข้ม แบ่งกลุ่มด้วยระยะห่างและเส้นขอบบาง ลดพื้นสีซ้ำทุกการ์ด ใช้สีเขียวเข้มเป็นสีการกระทำหลักตาม DESIGN.md ฉบับล่าสุด และสีสถานะเฉพาะตำแหน่งที่สื่อความหมาย กราฟยังเป็นองค์ประกอบหลัก ไม่เปลี่ยนหน้าแรกให้เป็นรายการงานอย่างเดียว

ใช้ฟอนต์ไทยเดิมที่อ่านง่าย เช่น Sarabun; body ราว 16px ข้อความรองไม่เล็กจนอ่านมือถือยาก ระยะบรรทัดภาษาไทย 1.5–1.7 ตัวเลขเรียงหลักสม่ำเสมอ หน่วยอยู่ใกล้ค่าและไม่แสดงทศนิยมเกินจำเป็น

## สีและความหมาย
| ความหมาย | สีที่เสนอ | ข้อกำหนด |
|---|---|---|
| เร่งตรวจสอบ | แดงเข้ม | ข้อความ + ไอคอน ไม่ใช้พื้นแดงทั้งหน้า |
| ควรตรวจสอบ | ส้ม/อำพันเข้ม | เห็นต่างจากเร่งตรวจสอบ |
| เฝ้าติดตาม | น้ำเงิน | ไม่ใช้สีเดียวกับปัญหาด่วน |
| ไม่พบสัญญาณผิดปกติ | สีเป็นกลาง มีเขียวได้เล็กน้อย | ไม่สื่อว่ารับรองอุปกรณ์สมบูรณ์ |
| ข้อมูลไม่ครบ/รอยืนยัน | เทา พร้อมไอคอนข้อมูล | แยกจากระดับความสำคัญ |

สถานะงานใช้ป้ายแบบเส้นขอบ/ข้อความ เพื่อไม่แข่งกับป้ายความสำคัญ ชื่อสถานะต้องอ่านได้โดยไม่ต้องจำสี ใช้ contrast อย่างน้อย 4.5:1 สำหรับข้อความทั่วไปและ 3:1 สำหรับตัวควบคุม/กราฟที่จำเป็น มี focus ที่มองเห็น

## องค์ประกอบหลัก
- Header: ชื่อหน้า เดือนที่เลือก ขอบเขต และการกระทำหลักหนึ่งอย่าง
- KPI: ตัวเลข คำอธิบาย ฐานเปรียบเทียบและความครอบคลุม ห้ามตกแต่งด้วยเปอร์เซ็นต์ที่ไม่มีฐานจริง
- การ์ดตรวจสอบ: ชื่อไซต์ → ความสำคัญ/สถานะงาน → เหตุผล → ค่าหลักฐาน → ดูรายละเอียด
- Evidence panel: หัวข้อ “ข้อมูลที่พบ”, “สาเหตุที่เป็นไปได้”, “ตรวจอะไรต่อ” แยกพื้นที่อ่านชัดเจน
- แบบบันทึกผล: label ชัด บอกช่องบังคับ เก็บ input เมื่อผิดพลาด แสดงกำลังบันทึกและผลจริง
- ข้อมูลเทคนิคใช้ disclosure; glossary เปิดจากคำศัพท์ได้ทั้งเมาส์ แป้นพิมพ์และการแตะ

## กราฟ
- กราฟหลักตอบว่าแนวโน้มผลผลิตเปลี่ยนอย่างไร: 12 เดือน มีหน่วยแกนและเดือน/ปีชัดเจน
- ชุดข้อมูลปีปัจจุบัน/ปีก่อนแยกทั้งสีและรูปแบบเส้น ไม่ใช้สีใกล้กันทั้งหมด
- กราฟพลังงานใช้สีประจำชุดอย่างสม่ำเสมอ เช่น ผลผลิตเขียวเข้ม ปีที่ผ่านมาอำพันพร้อมเส้นประหรือแท่งลาย
- ช่องไม่มีข้อมูลเป็นช่องว่าง ไม่ลากผ่านโดยไม่อธิบายและไม่แทนด้วยศูนย์
- Tooltip ใช้ได้ด้วยการแตะและแป้นพิมพ์ มีสรุปข้อความ/ตารางเป็นทางเลือก
- คำสรุปกราฟคำนวณจากข้อมูลจริง ไม่แต่งคำวินิจฉัย และระบุ baseline
- หลีกเลี่ยง gauge หรือ pie ที่ไม่ได้ช่วยตัดสินใจ ไม่จัดอันดับประสิทธิภาพจาก kWh ดิบข้ามไซต์ต่างขนาด
- ยอดรวมที่ข้อมูลไม่ครบมีหมายเหตุครอบคลุมกี่ไซต์; เปลี่ยนขอบเขตแล้วกราฟและ KPI ใช้ฐานเดียวกัน

## Responsive
Desktop: เมนูแนวนอนด้านบนสูง 69px และแถบไซต์ชิดซ้าย 310px ตามภาพ Inspection Desk ที่เลือก; รายละเอียดไซต์วางกราฟเต็มความกว้าง ตามด้วย KPI ในกรอบกราฟ และสามคอลัมน์ผลตรวจ/ประวัติซ่อม/AI ตารางไซต์รองรับการเรียง/กรอง

Mobile: เมนูหลัก 4 รายการเข้าถึงง่าย; KPI เรียงตามพื้นที่; กราฟทีละอัน; รายการไซต์เป็นการ์ด; ปุ่มสัมผัสอย่างน้อย 44×44px; ชื่อไซต์ไทยยาวขึ้นบรรทัดได้; ไม่มี horizontal overflow ของทั้งหน้า ตารางเทคนิคอนุญาตเลื่อนเฉพาะกรอบพร้อมสัญญาณบอก

ทดสอบอย่างน้อยความกว้าง 390px และ 1440px รวม zoom 200%, ชื่อไซต์ยาว, ตัวเลขใหญ่, รายการว่าง, loading/error, disclosure และปุ่มย้อนกลับ ไม่แก้ล้นโดยซ่อน overflow ของทั้งหน้า

## คำในหน้าจอ
ใช้ “ไฟที่ผลิตได้ (หน่วย)” พร้อมอธิบาย 1 หน่วย = 1 kWh; “กำลังติดตั้ง (kWp)” เป็นรายละเอียด; ใช้ “ยังประเมินไม่ได้” เมื่อหลักฐานขาด หลีกเลี่ยง “เครื่องเสีย”, “อันตราย”, “ปกติแน่นอน” จากรายงานรายเดือน

ตัวอย่าง wireframe และข้อมูลจำลองต้องระบุว่าเป็นตัวอย่าง ห้ามแสดงสถานะบันทึกสำเร็จ ซิงก์อัตโนมัติ หรือผลตรวจช่างที่ยังไม่มีระบบรองรับ

มือถือใช้ปุ่ม “ไซต์ทั้งหมด · เลือกไซต์” เปิดแถบค้นหาและสลับไซต์ กราฟและรายการยังอยู่ในลำดับหลัก เมื่อสลับไซต์ให้ปิดแถบและรักษาเดือน/ขอบเขตเดิม
